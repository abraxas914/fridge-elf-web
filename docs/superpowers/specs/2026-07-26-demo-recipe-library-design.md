# Web Demo 预设食谱库与彩色食材图标设计

日期：2026-07-26

状态：设计已确认，待书面复核

范围：仅限网页 `/demo`

不涉及：Android/原生客户端、后端 API、Agent 网关、图片接口、Vercel 环境变量与防火墙

## 1. 目标

把现有 Web Demo 的 5 份演示食谱扩展为 55 份可实际浏览和使用的食谱：

- 从 `Gar-b-age/CookLikeHOC` 中选择并重新整理 50 份食谱，覆盖其全部 15 个菜品类别。
- 新食谱同时出现在普通食谱浏览、个人收藏、周规划和 AI 食谱插画工作台中。
- 用户可按类别、标题、食材和标签快速找到食谱，并在采取操作前查看真实食材和步骤。
- 收藏、周规划、购物缺料和 AI 插画消费同一份食谱事实数据。
- 增加一组高辨识度彩色食材 SVG，重点补齐茄子、牛油果等现有目录缺口；已有香蕉图标只优化，不重复建 key。
- 不在用户界面、内置数据或生成提示中出现来源项目的品牌用语。

## 2. 产品边界

本次只完善无状态 Web Demo 的前端模拟体验：

- 不修改 `api/**`、`vercel.json`、后端请求协议或任何密钥配置。
- 不把新食谱同步到 Android WebView、原生数据库、MQTT 或其他客户端。
- 不在运行时请求 GitHub；食谱以经过人工整理的静态种子随前端构建发布。
- 不保存 AI 生成的图片；图片工作台继续消费已有 `/api/illustrate` 能力。
- 不引入完整的 `RecipeStoreV2`，避免在冲刺阶段扩大迁移范围。

## 3. 来源与内容安全

来源仓库没有提供可识别的顶层许可证文件，README 还说明部分文字来自外部资料。因此本次只把该仓库作为事实线索，不直接复制其受保护表达。

允许进入 Demo 的内容：

- 菜名的通用事实表达；
- 食材名称和来源中明确给出的用量；
- 烹饪动作、顺序、火候、时间和完成标准等事实；
- 原始类别到 Demo 类别的映射。

禁止进入 Demo 的内容：

- 来源图片、图片 URL、HTML、供应商介绍、采购信息和营销文案；
- 大段原文或对步骤文字的机械复制；
- 来源项目的品牌名称、门店名称或定制产品名称；
- 来源中没有提供的用量、时间、火候或完成标准。

每份食谱都要用简洁中文重新表述。缺失字段保持缺失，不通过模型或开发者主观补造。

## 4. 食谱数据模型

继续使用现有 `SavedRecipe` 和 localStorage key，只增加可选字段：

```ts
type RecipeCategory =
  | '主食'
  | '凉拌'
  | '卤菜'
  | '早餐'
  | '汤'
  | '炒菜'
  | '炖菜'
  | '炸品'
  | '烤类'
  | '烫菜'
  | '煮锅'
  | '砂锅菜'
  | '蒸菜'
  | '配料'
  | '饮品'

interface RecipeIngredient {
  key?: FoodKey
  name: string
  amount?: string
}

interface SavedRecipe {
  // 既有字段保持不变
  id: string
  key: FoodKey | 'unknown'
  name: string
  cn: string
  kcal: number | null
  time: number
  tags: readonly string[]
  match: boolean
  need: readonly string[]
  desc: string
  steps?: readonly string[]

  // Web Demo 增量字段
  category?: RecipeCategory
  ingredients?: readonly RecipeIngredient[]
  source?: 'seed' | 'user' | 'assistant'
}
```

兼容规则：

- `id` 是收藏和周规划的持久化主键，内置食谱发布后不得改名。
- 新内置 ID 使用 `recipe-[a-z0-9-]+`，全部唯一且稳定。
- `need` 继续保留，供旧 UI 和购物逻辑兼容；新种子同时提供结构化 `ingredients`。
- `ingredients[].key` 只使用存在于 `FoodKey` 的值；没有可靠映射时只写中文 `name`。
- `steps` 为真实步骤，建议 3–8 步；插画单页需要时按顺序压缩为最多 6 步。
- 中文标题尽量不超过 12 个字，保证卡片和插画标题可读。
- `kcal` 无可靠来源时写 `null`；`time` 因既有类型要求使用 `0` 表示未知，界面在 `time <= 0` 时隐藏用时，不伪造精确营养或时长数据。

## 5. 种子合并与持久化

现有 `fridge-favorite-recipes-v1` 不改 key，避免让当前 Demo 状态整体失效。加载时从“仅首次读取种子”改为稳定 ID 合并：

1. 读取现有 localStorage 数组。
2. 对已知内置 seed ID，使用当前构建中的 canonical seed 刷新内容。
3. 把本次构建缺失的内置 seed 按定义顺序追加进去。
4. 保留 `source: 'user' | 'assistant'` 以及无法识别为内置 seed 的旧自定义记录。
5. 不修改已有周规划中的食谱 ID。
6. 周规划若遇到已不存在的自定义食谱 ID，继续使用现有安全回退，不因迁移崩溃。

内置 seed 是 Demo 内容，不允许在“个人收藏”中编辑或删除，避免刷新后再次出现造成误解；用户和 Agent 创建的食谱仍保持可编辑、可删除。

本次不增加 seed version、数据库迁移器或跨设备同步。

## 7. 共用食谱选择器

新增 `RecipeCatalogPicker`，由普通食谱浏览、周规划和 AI 食谱插画工作台共用，避免三套筛选逻辑逐渐分叉。

选择器包含：

- 搜索框：匹配中文/英文标题、食材、标签。
- 类别下拉：`全部类别` 加 15 个固定类别。
- 结果计数：例如 `炒菜 · 6 道` 或 `共 55 道`。
- 双列紧凑卡片：显示主食材图标、中文标题、类别、用时和关键标签。
- 明确的选中态、键盘焦点和空结果提示。
- 当前食谱预览：显示主图标、类别、标签、用时、结构化食材和真实步骤。

55 条数据不需要虚拟列表；筛选结果使用 memoized 计算即可。窄屏退化为单列卡片，弹窗不产生页面级横向溢出。

## 8. 三处入口行为

### 8.1 普通食谱浏览与个人收藏

- “个人收藏食谱”继续是普通浏览入口，但内容升级为完整 Demo 食谱库。
- 默认展示全部 55 份，可搜索和按类别筛选。
- 点击卡片打开真实详情，不再统一显示通用四步模板。
- 内置 seed 展示“演示食谱”状态，不显示编辑、删除动作。
- 用户和 Agent 创建的食谱继续显示现有编辑、删除动作。
- 收藏/周规划/购物入口仍从同一 `SavedRecipe` 记录读取。

### 8.2 周规划

- 选择早餐、午餐或晚餐的弹窗使用同一选择器。
- 先选择食谱并预览，再点击 `加入这餐`；选择动作本身不立即写入计划。
- 加入后保存稳定 recipe ID，现有周计划不因 seed 内容刷新而失效。
- 搜索和类别筛选只影响候选列表，不影响已排入的餐次。

### 8.3 AI 食谱插画

- 保留现有“选择食谱 / 粘贴食谱”两种输入方式。
- “选择食谱”模式使用同一选择器和 55 份种子。
- 选择后展示真实食材与步骤，再进入已有四种插画风格和单图生成流程。
- 输出仍然只有一张图片；不新增食谱文本生成接口。
- “粘贴食谱”模式保持现有前端解析和无状态行为。

## 9. 真实食谱消费链

详情、购物和插画必须优先消费真实数据：

```text
canonical seed
  ├─ category / tags ──> catalog filters
  ├─ ingredients ──────> detail + shopping resolver + illustration
  └─ steps ────────────> detail + illustration
```

兼容回退只用于旧自定义记录：

- 有 `ingredients` 时，详情和插画使用结构化食材。
- 无 `ingredients` 时，才从旧 `need` 生成兼容显示。
- 有 `steps` 时，详情和插画使用真实步骤。
- 无 `steps` 时，才使用现有通用步骤模板。

购物缺料解析统一经过 `foodCatalog` 的中文名、英文名与 aliases。能映射为 `FoodKey` 的食材显示标准目录名称和 SVG；不能映射的食材保留原中文名，并使用通用食品盒图标。

## 12. 错误、空态与可访问性

- 搜索无结果：显示 `没有找到符合条件的食谱`，提供清除筛选动作。
- 食谱缺少真实步骤：仅对旧自定义食谱显示兼容模板，不让页面空白。
- 食材无法映射：保留原名称和通用图标，不丢弃食材。
- 类别选择使用原生或可访问的 `<select>`，有明确 label。
- 卡片使用按钮语义，支持键盘选中；选中状态通过文字/边框和 `aria-pressed` 表达，不只依赖颜色。
- 长食材和步骤在预览区换行，移动端弹窗可纵向滚动。
