# Fridge Elf Landing 真实硬件显影设计规格

日期：2026-07-26

状态：视觉方向已确认，待书面确认

范围：`/` Landing Page 的家庭 AIoT 章节

不涉及：`/demo`、API、Android、固件能力、Release 契约与部署架构

## 1. 目标

在现有像素品牌插画与长页叙事中加入一张真实的黑客松原型照片，让页面清楚证明：

- Fridge Elf 已经运行在真实硬件上；
- 冰箱旁终端和手机端共同构成家庭 AIoT；
- 概念插画表达的同步关系已经落到可运行原型。

照片不作为 Hero 装饰，也不新增独立的“技术展示”章节。它放在 `家庭 AIoT` 章节内，成为现有设备同步插画的最终实景状态。

## 2. 素材筛选

本轮 Landing 只采用一张真实硬件照片：

```text
codex-clipboard-ec9eb360-effe-4100-8bf1-bd14644c4d80.png
```

选择理由：

- 同一画面包含手机端、硬件终端和真实接线；
- 能直接证明两端共享产品状态；
- 黑客松现场物件保留了开发过程的可信度；
- 横向构图适合现有家庭 AIoT 章节和桌面、移动端布局。

其余四张候选图本轮不进入 Landing：

- 竖版海报包含大量已经烘焙进图片的文案，放入长页会重复叙事；
- 两张像素品牌效果图更接近宣传渲染，无法提供新增的真实性；
- 冰箱安装效果图适合作为后续宣传图，但目前同样包含较多图片内文案，且与真实开发现场图同时出现会混淆“原型”和“理想生活场景”。

不删除或覆盖用户提供的任何原图。

## 3. 页面位置与叙事

保留当前章节顺序：

1. 日常问题
2. 食材生命周期
3. 家庭 AIoT
4. 多模态入口

家庭 AIoT 章节内部的视觉顺序调整为：

```text
章节文案与共享库存标签
→ DeviceSyncSvg 解释同步关系
→ 真实原型照完成硬件显影
→ 进入多模态章节
```

照片不增加新的 Header 锚点，不改变 `#iot`，也不扩大页面导航层级。

图片附近只保留一行克制说明：

```text
手机端与冰箱终端，共享同一份正在流动的库存。
```

不展示开发板型号、协议、供应商、模型名或其他底层技术栈。

## 4. 过渡机制

桌面端在同一个视觉槽位叠放两层：

- 初始层：现有 `DeviceSyncSvg`；
- 最终层：真实硬件照片。

当 `#iot` 章节进入可视区域并且照片已经加载完成后：

1. 同步插画轻微上移并降低透明度；
2. 照片通过 `clip-path`、`opacity` 和轻微 `transform` 快速显影；
3. 过渡完成后保持静态，不循环、不自动切回。

过渡只动画合成友好的属性，不改变章节尺寸，不制造布局跳动。总时长控制在约 `700ms`，使用现有 `--ease-out`，不使用弹跳、缩放冲击或大幅视差。

照片加载失败时，插画保持可见，页面不会出现空白视觉槽位。

## 5. 移动端与减少动态效果

在不大于 `800px` 的现有移动断点中：

- 关闭叠层显影；
- 同步插画与真实原型照改为自然纵向排列；
- 照片按原始宽高比完整显示，使用 `object-fit: contain` 和稳定的中心构图；
- 页面不得产生横向溢出。

在 `prefers-reduced-motion: reduce` 下：

- 关闭 `clip-path`、`opacity` 与 `transform` 过渡；
- 插画与照片直接进入稳定状态；
- 不影响文字、替代文本和阅读顺序。

如果桌面端实现后的实测过渡不够自然，允许整体降级为移动端的静态排列，不保留质量不足的动画。

## 6. 影调与视觉处理

原图保留真实构图，不生成或替换其中的设备、手机、线缆、贴纸和现场物件。

视觉处理目标：

- 降低偏橙饱和度；
- 轻微提亮中间调；
- 压低过强对比度；
- 让墙面和灯板高光靠近现有奶油色背景；
- 保留黑色屏幕、边框和线缆的清晰度。

实现采用可复核的固定影调处理和轻量色彩覆盖，不使用生成式重绘。最终页面资源转换为版本化 WebP，避免缓存旧图：

```text
/assets/hardware/fridge-elf-prototype-01-v1.webp
```

图片配置位于：

```text
src/landing/hardwareShowcase.ts
```

配置只保存中性资源路径，不保存“风格名”、生成工具名或内部工作流信息。

## 7. 组件边界

新增：

```text
src/landing/HardwareProofVisual.tsx
src/landing/hardwareShowcase.ts
```

`HardwareProofVisual` 负责：

- 渲染现有 `DeviceSyncSvg` 和真实照片；
- 在照片成功加载后设置就绪状态；
- 输出过渡所需的稳定类名和 `data` 状态；
- 提供图片尺寸、延迟加载、异步解码和替代文本；
- 在加载失败时保留现有插画。

`LandingPage` 只负责在家庭 AIoT 章节使用该组件，不维护图片加载或动画状态。

样式继续放在 `src/LandingPage.css`，复用现有颜色、边框、阴影、Motion Tokens 与 `800px` 断点，不引入新的设计体系。

## 8. 可访问性与性能

照片替代文本：

```text
同时运行 Fridge Elf 的手机端与冰箱硬件终端原型
```

实现要求：

- `<img>` 显式声明宽高，避免累计布局偏移；
- 使用 `loading="lazy"` 和 `decoding="async"`；
- 只加载一张版本化 WebP；
- 不新增自动轮播、计时器、滚动监听或第三方动效库；
- 键盘和屏幕阅读器阅读顺序与视觉顺序一致；
- 图片加载失败时不显示破损图标或空白框。

## 9. 测试与验收

单元测试：

- 硬件图片配置只包含批准的中性版本化路径；
- 家庭 AIoT 章节包含硬件证明组件；
- 图片具有正确的 `src`、宽高、替代文本、延迟加载和异步解码属性；
- 图片加载前保留插画状态；
- 图片成功加载后进入就绪状态；
- 图片失败时仍保留插画。

端到端测试：

- 桌面端滚动到 `#iot` 后，真实照片成功加载并完成一次显影；
- 显影过程中章节高度不变化；
- `360 / 412 / 480` 宽度下采用静态纵向布局且页面无横向溢出；
- `prefers-reduced-motion` 下无硬件显影动画；
- `/demo` 路由、长页导航和现有食谱作品墙保持可用。

生产验证：

```text
npm run build
npm run test:rth-html
npm run e2e
```
